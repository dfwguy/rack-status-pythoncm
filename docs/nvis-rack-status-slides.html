NVIS Rack Status

Flask dashboard for rack validation, Slurm, logs, and operations

NVIDIA rack status / NEMO visibility

What is NVIS Rack Status?

  • Single-page operations + visibility UI for data-center racks
  • Built with Python / Flask + templates/index.html
  • Talks to cmsh, Slurm, and bundled shell tools under bin/scripts/
  • Optional PAM login (same password as OS login for a chosen user)

Who is it for?

  • Field / platform engineers running NEMO singlerack validation
  • Anyone who needs one place to see rack state, logs, parser charts, and actions
  • Teams that already use rack_status.sh, parser.sh, and Slurm on the dashboard host

High-level architecture

  • backend/ — Python backend package (run with cwd at the repo root)
  • backend/app.py — routes, JSON APIs, background threads for long jobs
  • backend/native_status.py — builds the default status table (cmsh + ds + Slurm + log probes)
  • bin/scripts/ — rack_status.sh, parser.sh, power/GPU/NVSwitch helpers, etc. (repo root)
  • var/cache/ — cached probe JSON, rack list, log analysis (repo root; tunable via env)

Main screen

  • Rack table — one row per rack: validation state, last job, sinfo, device status
  • Log directory — working tree for logs and many subprocess cwds
  • Refresh — polls /api/status (background refresh optional)
  • Theme — dark / blue / light
  • Per-rack comments stored server-side

Where the data comes from

  • cmsh — rack list; ds device / tray tokens for the device column
  • Slurm — sinfo-style summary, job id, optional cancel / drain / undrain
  • Log probes — rack_status.sh --probe-json (cached) for NCCL / LLM heuristics
  • Optional physical_rf0 map from cmsh foreach

Parser & charts

  • [results] → parser.sh --json on the best NEMO log for that rack
  • NCCL summaries, bus_bw vs message size, Nemotron step time vs iteration
  • Optional Grafana embeds (GPU thermal / power) via RACK_WEB_GRAFANA_*
  • Export: Excel / CSV, log zip — gated on log heuristics and NEMO “done” where configured

Validation & workloads

  • Run validation — bundled singlerack script, sync or async + status polling
  • Nemo xrack, Llama, mnubergemm stress — async APIs + status endpoints
  • Precheck / sysinfo — async or streaming where implemented
  • Shared pattern: job_id → poll status → toast / spinner on the rack row

Slurm from the UI

  • Modals: squeue, sinfo -R --long (table layout when parseable)
  • Drain / undrain for rack CT bracket via scontrol
  • scancel on last job when rules allow
  • Env: RACK_SLURM_MODULE, skip module load, binary overrides, feature toggles

Power & device operations

  • Power on, GPU reset, services restart — sync + async
  • HW check — presets / checker args
  • Row spinner + highlight while async work runs; hover for live stdout/stderr panel

NVLink / NVSwitch

  • NMXC cycle — nvswitches_rack_audit.sh --fix (whole rack)
  • NVSwitch check (streaming), SDN reset, system reset, IMEX check/reset
  • NVLMAPPER — stage under reports, run_nvlmapper.sh (embedded YAML + RC merge), zip download

Reports & downloads

  • Bug reports / reports — async generation, inventory under configurable dir (e.g. /home/cmsupport/reports)
  • Download nvidia-bug-report*.log.gz and nvlmapper.*.zip from inventory
  • Rack log open / tail and Slurm job stdout fetch/download

Streaming APIs

  • Live tail of job stdout or log files (SSE-style streaming endpoints)
  • sysinfo and nvswitch audit stream variants for long output

Security & configuration

  • RACK_WEB_AUTH_* — PAM, session secret, cookie flags for HTTPS
  • RACK_STATUS_LOG_DIR, RACK_STATUS_* — logs, cache, background interval
  • Many endpoints can be disabled per env (Slurm, features, etc.)

API surface (grouped)

Status: /api/status, /api/multirack-status, /api/app-stats
Jobs: validation, power, GPU, services, HW, NVSwitch/NMXC, IMEX, NVLMAPPER, precheck — mostly POST …-async + GET /api/reset-job-status
Slurm: squeue, sinfo, drain, undrain, scancel, job stdout
Parser: results, export excel/csv, Grafana live charts
Reports: bug-report async, inventory, file download

How to run it

cd nvis-rack-status
python3 -m venv .venv && source .venv/bin/activate
pip install -r backend/requirements.txt
export PORT=5000   # optional
python3 backend/app.py

See README.md and the backend/app.py module docstring for full env reference.

Summary

  • One dashboard for validation state, Slurm, and rack ops
  • Deep integration with your cluster scripts, not a separate SaaS
  • Extensive REST + streaming API for automation or custom UI
