## Decisions waiting on you

These are the only things blocking further progress. Everything else is either done or has no
dependency on you.

### 1. The five `RACK_WEB_OIDC_ISSUER` values — blocks the OIDC cutover

Each deployment needs its own, set to the URL operators actually reach the dashboard on, because
conforming OIDC clients compare `iss` by exact string. `https://…` normally; `http://localhost:PORT`
is accepted specifically because these are reached through SSH tunnels.

| Deployment | Value |
|---|---|
| Mayo Clinic | ? |
| Nscale TX | ? |
| Nscale NC | ? |
| Firmus (MEL01) | ? |
| Boston Markley | ? |

Lower risk than it was: startup now **refuses** with the variable named if the provider is on and
the issuer is missing or malformed, so a misconfigured deployment fails the way a deploy is built to
catch. Before that guard it booted green and every sign-in failed at token-mint time.

### 2. When to run the cutover

Flipping `RACK_WEB_OIDC_ENABLED` ends every live session, once. It is a scheduled event, not a
runtime toggle, and flipping it back signs everyone out a second time. Deleting the flag and the
HS256 path (FR-19b/AC-32) follows it.

### 3. AC-28b cannot land until the test suite stops bypassing the gate

The guard is written and tested (`web_auth._store_holds_a_claimed_account`) but **deliberately not
wired**, with the swap documented at the call site. Measured: `identity/testing.py` enrols a real
principal, which *is* a claimed account, so the guard correctly disables the bypass and 154 tests
fail. AC-28b and the bypass are mutually exclusive the moment tests authenticate for real.

The brief records FR-18c as depending on FR-18b but **not** that AC-28b does too. That is a
requirements gap, and the sequencing decision is yours: finish the suite migration first (below),
or accept the guard staying unwired for now.

### 4. Monaco costs ~5 MB of bundle

The SPA went 8.1 MB → 13 MB. That is inherent to Monaco and it is lazily loaded, so it never
reaches the initial bundle. Flagging it because air-gapped image size is a real constraint here. The
alternative is a plain textarea with server-side validation only, which loses as-you-type schema
validation and action completion.

## Defects found and fixed

Worth reading, because several were live and none was found by reasoning alone.

* **NPI catalog import was dead in every container.** `tomllib` is Python 3.11+; the runtime image
  is `ubuntu:22.04` → 3.10.12. CI runs 3.12, so it passed every test and failed only in the
  container — `local-vs-ci-tree` with the image as a third tree nobody tests. Two faces: the boot
  path swallowed it at *debug* level, and `POST /api/catalog/npi-tools/import` returned 500. Fixed
  with `backend/toml_compat.py`; verified on the real 3.10.12 image.
* **The durable operator label was forgeable.** Rack lock claims and validation activities took
  their operator from the client-supplied `X-Rack-Operator` header, so "who locked this rack" was
  unprovable. Now the authenticated principal.
* **`.env.example` was misleading in three ways at once** — it advertised two deleted auth
  variables, six of eleven keys were inert, and three of the six Compose actually interpolates were
  missing, including `RACK_WEB_BIND_ADDR`, whose absence exposed the dashboard on the Nscale TX OVA.
* **An unresolvable target returned 403 when 400 is honest.** A request that never named its target
  is malformed, not forbidden; "not authorized" sent callers chasing permissions they already held.
* **Monaco defaults to a CDN**, which would silently never load on an air-gapped host — the same
  failure the Kaizen CSS already paid for. Bundled locally, JSON-only, verified by grepping the
  build for `cdn.jsdelivr.net`.
* **Four defects in `config_registry.py` found by an independent design review**, two of which would
  have refused startup on real deployment shapes. One was mine violating a rule I had written two
  declarations earlier, and my own test asserted the defect rather than catching it.

## Mistakes of mine worth knowing about

* I installed the authenticating test client **globally** first, and it silently turned six real 401
  tests green — the blanket bypass again, pointed the other way. Authentication is opt-in now.
* Two wiring tests failed their own mutations because they asserted on `app.py` **source text**, so
  `pass  # config_preflight.run()` satisfied "is it called". Both walk the AST now. That was the
  second time in one day a source grep could not tell code from the comment beside it.
* The first `greenlight.toml.example` was unfit to hand anyone: five settings nobody configures, and
  a generator that broke words mid-token. Regenerated from the registry with a `--check` gate.
