# Building these docs

Not part of the site — Sphinx excludes this file. It is for whoever is editing the docs.

```bash
pip install -r docs/requirements.txt
sphinx-build -W --keep-going -b html docs static/docs
open static/docs/index.html
```

The app serves the built output at **`/docs/`**, so the documentation a deployment shows is
always the documentation for the code running there.

## Before you commit

```bash
python bin/check-docs-diataxis.py     # every page declares a mode, and it matches its section
```

CI runs it with the build, so skipping it just moves the failure.

## Two things that will bite you

**`-W` is not optional.** A warning here is a broken cross-reference or a page missing from
`_toc.yml`, and both are 404s for a reader. `nitpicky = True` in `conf.py` makes an unresolvable
`{doc}` reference a warning, and therefore an error.

**A new page must be added to `_toc.yml`.** `external_toc_exclude_missing = False` means a page
that exists and is listed nowhere fails the build. That is the check that stops a site
accumulating pages reachable only by search.

## The migration boundary

This repo has ~44 hand-written `SCREAMING_CASE.md` files that predate the site. They began at
`docs/` root and are now filed into topic subfolders — `clusters/` (customer/site runbooks and
RCAs), `networking/` (NCCL/fabric), `auth/`, `releases/`, `handovers/`, `integrations/`, `dsx/`,
and per-feature folders — to keep the root readable. They are **excluded** by the `[A-Z]*.md` and
`**/[A-Z]*.md` patterns in `conf.py` (the second keeps them excluded at any depth after the move),
not listed in `_toc.yml`, and not built.

That is a deliberate staging boundary, not neglect: converting all of them at once would be a
large unreviewable change, and several are incident write-ups and cluster runbooks that may
belong in `explanation/` or nowhere. To migrate one (from wherever it now lives):

1. Decide its Diátaxis mode — apply the compass in `.cursor/rules/docs-diataxis.mdc`, not the
   filename. Most of the existing files are `explanation` or `reference`; a few are genuinely
   how-to guides and need their titles rewritten to name a task.
2. Move it into that directory with a lowercase, hyphenated filename.
3. Add `diataxis: <mode>` frontmatter, plus a one-line `description:`.
4. Add it to `_toc.yml`.
5. Fix the cross-references that `-W` then complains about. This is the real work and the reason
   it is done a page at a time.

Two documents must **not** be migrated: `ACTION_VOCABULARY.md` and `action-vocabulary.json` are
generated by `bin/gen-action-vocabulary.py` and gated by CI. The site presents them the way this
note asks for — `bin/gen-action-vocabulary.py` writes a third output,
`reference/identity/action-vocabulary.md`, from the same registry, with the frontmatter the
structure gate requires. All three come from one renderer, so they cannot disagree, and
`--check` fails the build if any is stale.

That page exists because the list was invisible for months: `conf.py` excludes `[A-Z]*.md` by
design, so a reader looking for "which services and actions are there" found the *grammar* page
under `reference/identity/` and never the vocabulary itself.

## Where things live

| Path | What it is |
| --- | --- |
| `_toc.yml` | The whole site structure. A page listed nowhere fails the build. |
| `conf.py` | Sphinx config, plus the hook that renders the Diátaxis banner. |
| `_static/custom.css` | NVIDIA green overrides and the banner styling. |
| `index.md` | The landing page. |
