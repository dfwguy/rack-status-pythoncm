## 2. Endpoints no longer go in `app.py`

`app.py` had reached 20,000 lines with every feature touching it, which is exactly why your work
and ours collided. New endpoints now go in **`backend/api/`** — one module per domain, discovered
automatically at startup. You do not edit `app.py`, and you do not edit `backend/api/__init__.py`.

```python
# backend/api/rack_locks.py  ->  serves /api/rack-locks/...
from flask import Blueprint, jsonify

bp = Blueprint("rack_locks", __name__)   # no url_prefix -> derived from the filename

@bp.route("/claim", methods=["POST"])    # -> /api/rack-locks/claim
def claim(): ...
```

A module qualifies by exposing `bp` or `install(app)` (the latter for things Flask routing cannot
express, like the WebSocket terminal). Shared helpers go in `backend/core.py` if they are
Flask-free, or `backend/api/_common.py` if they build a response. **Never `from app import ...`
inside an `api/` module** — that recreates the import cycle the package exists to remove.

Also moved: `help`, `vault`, `history`, `terminal`. `/api/post-run-node-report` deliberately
stayed in `app.py` — it needs `_all_slurm_nodenames`, `_run_scontrol_node_update` and
`_operator_from_request` (46 call sites), which is more coupling than the move is worth today.

Full detail: `.cursor/rules/backend-api.mdc` (the recipe for migrating a domain),

## 4. One gap worth knowing

`bin/deploy-app.sh` syncs `backend/*.py` and the SPA — it does **not** sync `.cursor/rules/` or
`PLANNING_README.md`. That is the mechanical reason you never saw the new convention: we pushed
