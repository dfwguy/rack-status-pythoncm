## Entry Criteria

1. Requirements and acceptance criteria in the feature brief are approved by the developer — met: requirements milestone verified at v0.5.
2. Design components and interfaces in the feature brief are approved by the developer — met: design milestone verified at v0.6.
3. Test environments and fixtures listed in `Environments And Fixtures` are available or have a recorded plan to be available before execution.

## Exit Criteria

1. Every test case in this plan has been executed or has a recorded deferral reason.
2. Every acceptance criterion has at least one passing test case or a recorded deferral with an accepted reason.
3. Verification evidence for executed cases has been logged via `plc-evidence-ingestion` and is referenced from the feature brief.
4. Open issues from execution are filed as follow-up tasks with owners.
5. `python -m pytest backend/tests/ -v` and `ruff check` both pass, and `backend/tests/route_snapshot.json` is unchanged unless a route deliberately moved.

## Out-of-Scope Verification

1. **Authorization enforcement.** This phase records `decision` as `not-evaluated`; no policy is evaluated, so there is nothing to verify. Threats T-62 (enforcement must precede dispatch) and T-64 (default-deny, fail-closed) carry to Phase 3 as NFR-15 and NFR-16. Owner: Phase 3.
2. **Tamper evidence for the audit file** (threat T-51, candidate NFR-12). Deferred, so the trail is currently append-only by convention and an edit is not detectable. Owner: a later increment.
3. **Authenticated export API for audit records.** Deferred until after Phase 3, because authentication without authorization would let any operator read every other operator's actions. Owner: Phase 3+.
4. **External syslog / SIEM delivery as a configured default.** The sink exists and is opt-in; verifying delivery to a real collector needs infrastructure this plan does not assume. Owner: operator opt-in, plus a hardening profile later.
5. **Encryption of audit records in transit and at rest.** Not required for a local rotated file; adds key management to a first run. Owner: follows the identity work.
6. **Release-gate security scanning** (ScanSpect / nSpect under NSPECT-S57Q-EI19). Runs at the gate, not in this plan. Owner: release process.
7. **Sustained-flood resilience from an authenticated operator** (threat T-58). Rotation bounds disk and TC-14 proves the flood guard protects history from identical refusals, but a flood of *distinct* mutating requests with valid credentials is accepted as residual for Phase 1.
